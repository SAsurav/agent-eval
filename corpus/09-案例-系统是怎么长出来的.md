# 在不可控平台上建立可靠性 · 系统是怎么长出来的

> 来源：作品集《在不可控平台上建立可靠性》

整个系统不是一次写成的。目录里保留着 54 个探索脚本（t1 → t54），记录了从「能不能连上」到「端到端跑通」的完整路径。

这个顺序本身就是方法：每一层先证伪，再往上搭。在没有文档、没有官方接口的系统上，你能依靠的只有「试一次，看结果，再修正」。

| 阶段 | 脚本 | 在验证什么 |
| 连接 | t1–t9 | 能不能连上微信、能不能读到一个控件 |
| 交互 | t10–t20 | 右键菜单在哪、点什么坐标、焦点怎么守 |
| 选择 | t21–t34 | 选择窗口怎么开、搜索是否可靠、状态怎么读 |
| 数据 | t35–t49 | 标签成员存在哪（最终走到数据库的 protobuf 二进制字段） |
| 收口 | t50–t54 | 端到端、送达核验、批量边界 |
