# 领英目标职位抓取工作流

> 来源：内部项目/WORKFLOW.md

## 目标

从 LinkedIn 抓取指定公司**在东南亚**、**目前在职**、**符合指定职位**的员工，输出带超链接的 Excel。

---

## 核心文件（只需看这 5 个）

| 文件 | 作用 |
|---|---|
| `scrape.py` | **主程序**：登录态浏览器 → 搜索 → 三重筛选 → 写 `results.json` |
| `export_excel.py` | `results.json` → 桌面 Excel（姓名超链接） |
| `test_titles.py` | 职位匹配规则离线测试（改规则后必跑） |
| `extract_companies.py` | 从源 xlsx 的 A 列提取公司名单 → `companies.json` |
| `companies.json` | 目标公司清单（132 家） |

数据文件：`results.json`（抓取结果，逐家写入，可断点续传）

**不要外传**：`linkedin_state.json`、`edge_profile/`（含登录凭证）

其余 `geo_filter*.py` / `recon*.py` / `dump*.py` / `debug*.py` / `test6.py` / `fetch_html*.py` / `capture_api.py` 均为调试过程中的一次性脚本，可忽略。

## 环境要求

- Windows + **Edge**（用真实 Edge 驱动，非 Playwright 自带 Chromium，降低被识别风险）
- `E:\Anaconda\python.exe`（Python 3.11）
- `pip install playwright`（无需 `playwright install`，直接用 `channel="msedge"`）
- `openpyxl`（已装）
- **必须开 VPN 出境**（中国 IP 会被判到 `/check/china/add-phone` 手机验证页）

命令统一带编码前缀：`PYTHONIOENCODING=utf-8`

## 运行步骤

### 1. 首次登录（只需一次）

```bash
python login2.py
```

弹出 Edge 窗口，**手动登录**（脚本不接触账号密码）。登录成功后写入 `edge_profile/` 并保存 `linkedin_state.json`。

### 2. 抓取

```bash
python scrape.py companies.json
```

- 自动跳过 `results.json` 中已有的公司（断点续传）
- 检测到 `/check/` 或 `authwall` 跳转 → 立即中止整轮并保存

### 3. 导出

```bash
python export_excel.py
```

输出：`桌面\曼谷液冷论坛_目标职位筛选版.xlsx`（7 列；文件被 Excel 占用时自动另存带时间戳副本）

## 三重筛选逻辑（`scrape.py`）

### ① 地点：服务端 geoUrn 过滤

搜索 URL 带 `geoUrn` 数组，由 LinkedIn 服务端按**个人资料地址**过滤：

| 国家 | geo ID |
|---|---|
| 新加坡 Singapore | `102454443` |
| 马来西亚 Malaysia | `106808692` |
| 印尼 Indonesia | `102478259` |
| 越南 Vietnam | `104195383` |
| 泰国 Thailand | `105146118` |
| 菲律宾 Philippines | `103121230` |

这些 ID **无法从页面里直接读出**，只能用户在浏览器手动应用一次「地点」筛选后，从地址栏 URL 里复制。

### ② 在职：区分「目前就职」与「曾经就职」

卡片文本含两种行：

```
目前就职: Equinix - Regional Procurement Director
曾经就职: Equinix - Engineer
```

- **有「目前就职: 本公司」** → `strong`，可验证在职
- **仅「曾经就职」** → 剔除（已离职）
- **两者都无** → `weak`，暂留候补

### ③ 职位：10 类目标职位正则匹配

- `strong` 用「目前就职」里的**官方职位**匹配
- `weak` 用 `headline` 兜底

规则见 `scrape.py` 的 `TARGET_TITLES`。采购类要求「采购词 + 管理职级」双条件，排除 Coordinator/Analyst/Consultant。

### ④ 输出规则

- 每家**上限 10 人**，**不强制凑满**（精准优先）
- 有 1 个 `weak` 就往后多看 5 位（第 15 位），2 个看第 20 位，找到即提前截止
- 硬上限：4 页、单家 110 秒

## 关键坑（都是踩过的）

| 坑 | 现象 | 解法 |
|---|---|---|
| **中国 IP** | 跳 `/check/china/add-phone`，全部 0 结果 | 开 VPN；浏览器查 IP 用 `check_ip_browser.py`（curl 不走系统代理） |
| **两套 SDUI 渲染** | `div[data-view-name="people-search-result"]` 时有时无 | 改用 `[role="listitem"]`，两套变体都命中 |
| **解析提前 break** | `current`/`former` 恒为空，在职筛选失效 | 设完 `location` 后不能 break，后面还有「目前就职」行 |
| **翻页无上限** | 卡死 10 分钟 | `MAX_PAGES` + 单家 `BUDGET` 硬上限 |
| **并发抢配置目录** | 多个脚本同时开 Edge → 全 0 结果 | 同一时刻只跑一个脚本 |
| **Playwright 无默认超时** | 单次操作无限等待 | `set_default_timeout(20000)` |
| **无 API 捷径** | 试过 XHR 抓包（0 请求）、裸 HTTP（6.7KB 空壳） | 结果必须 JS 渲染，绕不过 |

## 邮箱问题（事实结论）

**LinkedIn 个人资料页不展示邮箱。** 只有 **1 度好友**的「联系信息」里能看到对方主动公开的邮箱，且多数人留空。

本工作流抓到的多为 2/3 度人脉，**拿不到邮箱**。补全需外部工具（Hunter.io / Apollo）按「姓名 + 公司域名」推断。
