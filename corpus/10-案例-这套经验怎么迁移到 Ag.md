# 在不可控平台上建立可靠性 · 这套经验怎么迁移到 Agent

> 来源：作品集《在不可控平台上建立可靠性》

Agent 也是一个不可靠系统。它和这套微信自动化面对的是同一类问题：

所以这套系统里的四个手段，可以直接搬过去：

• 数据库核验 → 用评测集核验输出，而不是相信模型自称做对了

• 重算未送达名单 → 每轮从真实状态重建，不依赖可能过期的记忆

• 匹配不唯一就拒发 → 不确定就转人工，不猜

• 焦点守卫 → 工具调用前校验前置条件，不满足就停

一句话：Agent 的质量问题，本质上和自动化脚本的可靠性问题是同一个问题──你不知道它下一步会做什么，所以你必须在它能做错的地方，提前放一个可验证的检查点。

| 这里 | Agent 里 |
| 控件对象不可信 | 模型输出不可信 |
| 右键可能落空 | 工具调用可能失败或选错 |
| 数据库快照会过期 | 上下文会被压缩、状态会漂移 |
| 消息发出去撤不回 | 副作用执行后无法回滚 |
